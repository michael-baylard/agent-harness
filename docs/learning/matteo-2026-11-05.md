## Interpretable Context Methodology

Paper: *Interpretable Context Methodology: Folder Structure as Agent Architecture*. Jake Van Clief and David McDermott. [PDF](https://arxiv.org/pdf/2603.16021) · [abs](https://arxiv.org/abs/2603.16021). Protocol is MIT, at `github.com/RinDig/Interpretable-Context-Methodology-ICM-`.

For a sequential workflow a person reviews at each step, numbered folders are the stages. Markdown files are the prompts. One agent reads the right files. Local scripts do the work that does not need a model.

| You want to | ICM |
|---|---|
| Change stage order | Rename or reorder folders |
| Change a prompt | Edit a markdown file |
| See intermediate state | Open the folder |
| Hand the workflow to someone else | Copy the folder |
| Recover from a failed step | Re-run that stage by hand |

It does not replace a framework when you need concurrent agents, programmatic branching, or automatic error recovery.

## Dream-RSI

Paper: *Dream-RSI: Recursive Self-Improvement through Evolving Worlds*. Tong Zheng and coauthors. [HTML](https://arxiv.org/html/2609.14858v1). Code: `github.com/zhengkid/Dream-RSI`.

The coding agent stays as it is. A thin layer controls branching, parallel tries, and stopping. Past discovery trees become a replay simulator. New exploration policies are tried on that recording, then the better policy goes back online.

Three stages: online explore, build the replay simulator, improve the policy by dreaming.
